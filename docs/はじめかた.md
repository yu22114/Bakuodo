# 爆踊 開発のはじめかた（運営メンバー向け）

Claudeを使って、自分たちでアプリを直せるようにするための手順書。
**レビュー係はいない。自分で出して、自分で確かめて、自分で戻す。**

専門用語は最小限にしてある。わからん言葉が出たらClaudeに「これ何？」と聞けばいい。

---

## 1. 環境の話（ここだけ先に理解して）

爆踊には **場所が2つ** ある。ここを混ぜると事故る。

| 場所 | たとえると | 誰が見る | 壊しても平気？ |
|---|---|---|---|
| **本番** | 駅に貼るポスター | 世界中 | 壊れる。でも数分で戻せる（→ 第5章） |
| **データベース** | みんなの名簿1冊 | 全員が同じ1冊を見る | **戻らない**（→ 第4章） |

試し刷り（プレビュー）は**使わないことにした**。開くのが面倒で誰も見なくなり、
確認したフリになっていたため。**直したら本番に出して、本番で見る。**
おかしければ戻す（→ 第5章）。戻すのは2〜3分で終わる。

**コピーが無いものが1つだけある。**

**データベース（Supabase）＝ みんなの名簿が1冊だけある状態**

サイファーの予定・参加者・アカウントが全部ここに入っている。
自分のパソコンで動かした時も含めて、**どこからでもこの同じ1冊**を見に行く。

- 画面のデザインを直す → 直すのは「紙」。何回でもやり直せる。**安全**
- データベースを直す → 直すのは「名簿そのもの」。**間違えたら戻らない。特別扱いする**

これが第4章の理由。ここだけ覚えて帰ってくれればいい。

---

## 2. 準備（1回だけ）

1. **Claudeの有料プラン**に入る（Pro以上）。各自で。アカウントの使い回しはしない
2. **GitHubのアカウント**を作る → 招待を受け取って承諾
3. ブラウザで **https://claude.ai/code** を開く → GitHubをつないで `Bakuodo` を選ぶ
4. Supabase の招待も来る（第4章のSQLを実行するため）。**普段は開かない。** 用があるのは
   SQL Editor と Advisors の2画面だけ
5. 本番のURLをスマホのホーム画面に置いておく（毎回ここで確認するため）

**インストールするものはゼロ。** ブラウザだけで動く。
自分のパソコンで動かしたい人は最後の「おまけ」へ。最初は要らない。

---

## 3. 毎回の流れ

```
① Claudeに日本語でお願いする
      ↓
② Claudeが直して「本番に出して」と言えば出る（数分で反映）
      ↓
③ 自分のスマホで本番を開いて確かめる   ← ここを飛ばさない
      ↓
④ おかしければ「さっきの変更を取り消して」と言う（→ 第5章）
```

**③を飛ばさない。** 出したまま見ないのが一番まずい。壊れていることに気づくのが
自分ではなく利用者になってしまう。

ただし**DBを変える時（第4章）とログイン周りだけは別**。ここはClaudeが先に説明してくる。
説明を読んでから出す。

### お願いのしかた（コツ）

良い例：

- 「LESSON画面のカードの日付が見づらいので、もっと大きくしてほしい」
- 「サイファー詳細ページに『雨天中止』の表示を出したい」
- （スクショを貼って）「ここのボタンが親指で押しにくい」

いまいちな例：

- 「なんかイケてない感じにして」→ どこを何にしたいか言う
- 「ついでにログイン周りも全部直して」→ **1回のお願いは1テーマ**。まとめて頼むと、どれが原因で壊れたのか分からなくなる

## 4. データベースを変えるとき（唯一の特別扱い）

「予約機能をつけたい」「項目を増やしたい」など、**名簿の形そのものを変える**話になると、
Claudeが `sql/` にファイルを作って「SupabaseのSQL Editorに貼って実行して」と言ってくる。
Claudeは自分でDBを触れないので、**実行するのは必ず人間**。ここが唯一、指が止まる場所。

### 覚えるのは1つ：**足し算だけする。引き算はしない**

| やること | 例 | なぜ安全か |
|---|---|---|
| ◯ 足す | 項目を増やす、表を増やす | 失敗しても**今あるデータは無傷**。コードを戻せば元通り |
| ✕ 消す | 使わない項目を消す、表を消す、名前を変える | **戻らない**。整理したい気持ちは捨てる |

使わなくなった項目は**消さずに放置していい**。散らかるが、それで誰も死なない。

見本：[`sql/2026-07-22_studio_fee.sql`](../sql/2026-07-22_studio_fee.sql) は「料金の項目を足す」だけの1行。
これくらいのサイズが理想。

### 順番

1. **先にバックアップを取る**（→ 第6章）
2. Claudeに「このSQLは何をするのか、失敗したら何が起きるのか」を日本語で説明させる
3. `DROP` `DELETE` `TRUNCATE` `RENAME` のどれかが入っていたら、**実行せずに一晩置く**。
   この4つだけが「戻らない命令」。翌日読み返して、まだ必要ならClaudeに足し算でやる方法を聞く
4. 実行したあと **Supabase → Advisors → Security Advisor** を開く。
   警告（赤や黄色）が出ていたら、その文をそのままClaudeに貼って直してもらう。
   ここを見ないと「新しく作った表が誰でも読み書きできる状態」に気づけない
5. アプリを触って壊れていないか確かめる

面倒なのはここだけ。画面の見た目をいじる分には、バックアップも確認も要らない。

---

## 5. 壊した時：本番を戻す

やらかしても慌てなくていい。**まず戻す。原因調査はその後。**

Claudeにこう言うだけでいい：

```
本番が壊れた。さっきマージした変更を取り消して、mainに戻して。
```

Claudeが「打ち消す変更」を作ってmainに入れる（`git revert` という操作）。
2〜3分で本番が元に戻る。**履歴は消えないので、この操作自体は安全。**

うまく言えない時のために、そのまま貼れる文：

```
直前のマージを git revert して push してほしい。
force push は使わないで。
```

> Vercelの管理画面を触れる人がいれば、Deployments → 「…」→ Instant Rollback のほうが速い（数十秒）。
> ただ上のやり方ならGitHubだけで完結するので、まずはこれを覚えればいい。

**戻せないのはデータベースの中身だけ。** だから第4章がある。

### テストで作ったサイファー・レッスンの消し方

本番で試すと、当然そのデータが本番に残る。**自分で片付けられる。**

プロフィール → **ACTIVITY** → **主催** → 🗑ボタン。終わったものも消せる。
参加者やジャンルの記録も一緒に消える。自分が主催したものだけが対象。

> 2026-08-17に「終わったサイファーを自動で消す仕組み」をやめた（開催履歴として残すため）。
> なので放っておくと溜まる。テストで作ったものは自分で消す。
> 参加したサイファーは、もう一度参加ボタンを押せば取り消せる。

## 6. バックアップの取り方

DBを触る前と、月1回。ターミナルで（できる人が代表で1回やればいい）：

```bash
npx supabase db dump --db-url "接続文字列" -f schema_$(date +%Y%m%d).sql
```

```bash
npx supabase db dump --db-url "接続文字列" --data-only -f data_$(date +%Y%m%d).sql
```

`db dump` は初期設定では**入れ物の形しか保存しない**ので、中身は `--data-only` で別に取る必要がある。2本セットで1組。

「接続文字列」は Supabase → Project Settings → Database → Connection string からコピーする。
**この文字列はパスワードそのもの。LINEやSlackに貼らない。**

面倒ならSupabaseの有料プラン（$25/月）にすると自動で毎日バックアップされる。人が増えるなら払ったほうが安い。

## 7. やっちゃいけないこと

1. **`SUPABASE_SERVICE_ROLE_KEY` を持ち出さない。** アプリの全権限マスターキー。Vercelの設定画面の中だけに置く。ブラウザ側のコードから使うのは絶対NG（全ユーザーのデータが誰でも書き換え放題になる）
2. **`.env` で始まるファイルの中身を人に見せない・チャットに貼らない**
3. **`git push --force` を許可しない。** Claudeがこれを提案してきたら断る。過去の履歴＝唯一の復元手段が消える
4. **通知（notifications）を作るコードを書かない。** 通知はDB側が自動で作る仕組み。手で作ると二重に飛ぶ
5. **同じ画面を2人で同時に触らない。** 「今日は俺がLESSON画面やる」とチャットで宣言してから始める
6. **金曜の夜と、イベント直前に本番へ出さない。** 壊れた時に誰も直せない時間帯に出さない、これはプロも守ってるルール
7. **わからないまま「OK」を押し続けない。** Claudeに「これ何をしてるの？中学生にわかるように説明して」と聞ける。聞くのはタダ

## おまけ：自分のパソコンで動かす（慣れてから）

1. Node.js をインストール（https://nodejs.org/ のLTS版）
2. ```bash
   npm install -g @anthropic-ai/claude-code
   ```
3. ```bash
   brew install gh && gh auth login
   ```
4. ```bash
   gh repo clone yu22114/Bakuodo && cd Bakuodo && npm install
   ```
5. `.env.local` というファイルを作って、`NEXT_PUBLIC_SUPABASE_URL` と
   `NEXT_PUBLIC_SUPABASE_ANON_KEY` の2行を書く（値は実装担当からもらう）
6. ```bash
   npm run dev
   ```

**注意：手元で動かしていても、データベースは本番と同じ1冊。** 手元でサイファーを削除すると本番からも消える。テスト用のデータで遊ぶこと。
