# 爆踊 開発のはじめかた

Claudeを使って、自分たちでアプリを直せるようにするための手順書。
レビュー係はいない。自分で出して、自分で確かめて、自分で戻す。

わからん言葉が出たらClaudeに「これ何？」と聞けばいい。聞くのはタダ。

---

## 1. これだけ覚える

**戻せるもの**：コード（画面の見た目・文言・並び順）。壊しても `git revert` で数分で戻る。

**戻せないもの**：データベースの中身。サイファーの予定・参加者・アカウントが入っている。
**1つしかなくて、全員が同じものを見に行く。**（自分のパソコンで動かしている時も同じ）

だから第4章だけ特別扱いする。それ以外は気軽にやっていい。

---

## 2. 準備（1回だけ）

1. **Claudeの有料プラン**に入る（Pro以上）。アカウントの使い回しはしない
2. **GitHubのアカウント**を作る → 招待を承諾
3. https://claude.ai/code を開く → GitHubをつないで `Bakuodo` を選ぶ
4. Supabase の招待も来る（第4章のSQLを実行するため）。**普段は開かない。**
   用があるのは SQL Editor と Advisors の2画面だけ
5. 本番のURLをスマホのホーム画面に置く

**インストールするものはゼロ。** ブラウザだけで動く。

---

## 3. 毎回の流れ

```
① Claudeに日本語でお願いする
      ↓
② Claudeが直してmainにpush → 数分で本番に反映
      ↓
③ 自分のスマホで本番を開いて確かめる   ← ここを飛ばさない
      ↓
④ おかしければ「さっきの変更を取り消して」と言う（→ 第6章）
```

出したまま見ないのが一番まずい。壊れていることに気づくのが自分ではなく利用者になる。

**DBを変える時（第4章）とログイン周りだけは別。** ここはClaudeが先に説明してくる。

### お願いのしかた

良い例：

- 「LESSON画面のカードの日付が見づらいので、もっと大きくしてほしい」
- （スクショを貼って）「ここのボタンが親指で押しにくい」

**1回のお願いは1テーマ。** まとめて頼むと、どれが原因で壊れたのか分からなくなる。

---

## 4. データベースを変えるとき（唯一の特別扱い）

「予約機能をつけたい」「項目を増やしたい」など、Claudeが `sql/` にファイルを作って
「SupabaseのSQL Editorに貼って実行して」と言ってくる。
**ClaudeはDBを直接触れないので、実行するのは必ず人間。**

### 覚えるのは1つ：**足し算だけする。引き算はしない**

| | 例 | |
|---|---|---|
| ◯ 足す | 項目を増やす、表を増やす | 失敗しても**今あるデータは無傷** |
| ✕ 消す | 項目を消す、表を消す、名前を変える | **戻らない** |

使わなくなった項目は消さずに放置していい。散らかるが、それで誰も死なない。

見本：[`sql/2026-07-22_studio_fee.sql`](../sql/2026-07-22_studio_fee.sql) は「料金の項目を足す」
だけの1行。このサイズが理想。

### 順番

1. **先にバックアップを取る**（→ 第5章）
2. Claudeに「このSQLは何をするのか、失敗したら何が起きるのか」を日本語で説明させる
3. `DROP` `DELETE` `TRUNCATE` `RENAME` が入っていたら実行しない。この4つだけが戻らない命令。
   Claudeに足し算でやる方法を聞く
4. 実行したあと **Supabase → Advisors → Security Advisor** を開く。
   警告が出ていたら、その文をそのままClaudeに貼って直してもらう。
   ここを見ないと「新しく作った表が誰でも読み書きできる状態」に気づけない
5. アプリを触って壊れていないか確かめる

面倒なのはここだけ。画面の見た目をいじる分には、バックアップも確認も要らない。

---

## 5. バックアップの取り方

DBを触る前と、月1回。ターミナルで（できる人が代表で1回やればいい）：

```bash
npx supabase db dump --db-url "接続文字列" -f schema_$(date +%Y%m%d).sql
```

```bash
npx supabase db dump --db-url "接続文字列" --data-only -f data_$(date +%Y%m%d).sql
```

`db dump` は初期設定では**入れ物の形しか保存しない**ので、中身は `--data-only` で別に取る。
2本セットで1組。

「接続文字列」は Supabase → Project Settings → Database → Connection string からコピー。
**この文字列はパスワードそのもの。LINEやSlackに貼らない。**

---

## 6. 壊した時：本番を戻す

やらかしても慌てなくていい。**まず戻す。原因調査はその後。**

Claudeにこう言うだけ：

```
直前の変更を git revert して push してほしい。force push は使わないで。
```

2〜3分で本番が元に戻る。履歴は消えないので、この操作自体は安全。

**戻せないのはデータベースの中身だけ。** だから第4章がある。

### テストで作ったサイファー・レッスンの消し方

プロフィール → **ACTIVITY** → **主催** → 🗑ボタン。終わったものも消せる。
参加したサイファーは、もう一度参加ボタンを押せば取り消せる。

---

## 7. やっちゃいけないこと

1. **`SUPABASE_SERVICE_ROLE_KEY` を持ち出さない。** アプリの全権限マスターキー。
   Vercelの設定画面の中だけに置く。ブラウザ側のコードから使うのは絶対NG
2. **`git push --force` を許可しない。** Claudeがこれを提案してきたら断る。
   過去の履歴＝唯一の復元手段が消える
3. **通知（notifications）を作るコードを書かない。** DB側が自動で作る。手で作ると二重に飛ぶ
4. **わからないまま「OK」を押し続けない。** Claudeに「これ何をしてるの？」と聞ける

---

## おまけ：自分のパソコンで動かす（慣れてから）

1. Node.js をインストール（https://nodejs.org/ のLTS版）
2. ```bash
   npm install -g @anthropic-ai/claude-code
   ```
3. ```bash
   brew install gh && gh auth login
   ```
4. ```bash
   gh repo clone yu22114/Bakuodo && cd Bakuodo && npm install
   ```
5. `.env.local` というファイルを作って、`NEXT_PUBLIC_SUPABASE_URL` と
   `NEXT_PUBLIC_SUPABASE_ANON_KEY` の2行を書く（値は実装担当からもらう）
6. ```bash
   npm run dev
   ```

**注意：手元で動かしていても、データベースは本番と同じ1つ。** 手元でサイファーを削除すると
本番からも消える。テスト用のデータで遊ぶこと。
